# КАССА — сайт работ

Портфолио Артёма Ткачева: витрина треков с обложками и плеером плюс отдельная
страница на каждый трек. Живой адрес: https://artkachev.github.io

Сделано по образцу credits.podlesnytwins.com, но с исправленными ошибками той
архитектуры — см. «Чего не делать».

## Из чего состоит

| Файл | Что внутри |
|---|---|
| `site.json` | Кто ты: имя, подпись, цвет, шрифты, роли, жанры, контакты |
| `data.json` | Работы: 86 релизов — 81 сингл и 5 альбомов, всего 100 треков |
| `faq.json` | Вопросы и ответы: разделы, вопросы, ответы, «коротко» |
| `artist_genres.json` | Артист → жанр, чтобы импорт сам расставлял фильтры |
| `covers/` | Обложки. Лежат в репозитории, а не грузятся со Spotify |
| `skill/` | Скрипты сборки. Чистый Python, ставить ничего не надо |
| `index.html`, `track/`, `faq/`, `sitemap.xml`, `robots.txt` | **Собираются скриптом. Руками не править** |

## Какие есть страницы

- **`/`** — витрина плитками. Сверху два ряда фильтров. Жанр — один из списка.
  Первое нажатие на обложку заодно заряжает трек в плеер, не включая звук:
  телефон разрешает автозапуск только внутри жеста пользователя, а загрузка
  идёт не мгновенно, поэтому раньше приходилось жать дважды.
  Ролей можно выбрать сразу несколько, и работа должна нести их все:
  «продакшн + сведение» показывает 61 работу, где сделано и то, и другое, —
  это не сумма двух списков. Ряды работают вместе, поэтому «поп + продакшн»
  тоже пересечение. Числа у кнопок живые: показывают, сколько останется,
  если включить этот фильтр поверх уже выбранных; кнопка, ведущая в ноль,
  гаснет. Роль альбома — объединение ролей его треков. Сингл играет в два шага:
  нажатие на обложку только выбирает трек и зажигает кнопку плей, звук
  запускает уже она — случайное касание ничего не включает. Альбом — одна
  плитка с бейджем «N треков», по клику открывается окно со списком.
- **`/track/`** — каталог работ: артисты по алфавиту, у каждого сначала
  альбомы со списком треков, потом синглы с годами. Указатель по буквам сверху.
  Есть поиск по артисту, альбому и названию трека. Он понимает и кириллицу,
  и латиницу в обе стороны: «клава» находит «Klava Koka». Работает это так —
  сборщик кладёт в `data-s` и сам текст, и его латиницу, а `hub.js`
  переводит запрос и сверяет с обеими формами.
- **`/track/<слаг>/`** — страница трека: обложка, роли, плеер, разметка
  MusicRecording для поиска.
- **`/faq/`** — вопросы и ответы, собираются из `faq.json`, размечены
  как FAQPage.

## Команды

```bash
python3 skill/scripts/portfolio.py --project . build              # пересобрать
python3 skill/scripts/portfolio.py --project . publish --confirm  # собрать и залить
python3 skill/scripts/portfolio.py --project . import "<ссылка Spotify>"
python3 skill/scripts/portfolio.py --project . roles roles.txt
```

С Claude Code можно просто словами: «добавь на сайт <ссылка>».

## Роли

У каждого трека в `data.json` есть поле `roles`. Они проставлены по всем ста
трекам из списка Артёма, менять нужно только при добавлении новых. Значения:

- `write` — написал
- `prod` — спродюсировал
- `mix` — свёл
- `master` — мастеринг

Можно несколько: `"roles": ["write", "prod", "mix"]`.

**Почему это важно.** Заголовок страницы трека берётся от первой роли по
старшинству `write > prod > mix > master`: «Кто написал», «Кто спродюсировал»,
«Кто свёл». Сейчас 77 страниц называются «кто спродюсировал» и 23 «кто свёл» —
это разные поисковые запросы. Именно страницы треков приносят людей из поиска,
поэтому у нового трека роль лучше ставить сразу, а не оставлять заглушку.

Пачкой удобнее через файл `roles.txt`, по строке на трек:

```
Журавли — Klava Koka — продакшн, сведение
Трезво — КАССА — написал, спродюсировал, свёл
```

Потом `roles roles.txt` → `build` → `publish --confirm`.
Строки, которые не совпали с названием, скрипт напечатает и не тронет.

## Альбомы

Релиз в `data.json` бывает двух видов. Сингл — `"type": "single"` с полем `id`.
Альбом — `"type": "album"` с `album_id` и списком `tracks`, у каждого трека
свой `id`, `title`, `artist` и роли. Страница у каждого трека альбома всё равно
своя, слаг тот же, что был у сингла, — старые ссылки не ломаются.

Сейчас альбомов пять: они собраны по хешу обложки (у треков одного релиза она
общая — это надёжнее поиска по названию), а названия взяты из открытого API
Deezer. Если появится ещё один альбом, проще всего импортировать его ссылкой:

```bash
python3 skill/scripts/portfolio.py --project . import "<ссылка на альбом Spotify>"
```

У сингла может быть поле `"album": "Название"` — тогда на странице трека
появится строчка «Из альбома «…»». Плитку это не меняет.

## Вопросы и ответы

Всё содержимое — в `faq.json`, HTML собирается из него. Структура: разделы,
внутри каждого список `{"q": вопрос, "a": ответ}`. В ответах работает
мини-разметка: `[текст](ссылка)` — ссылка, `**текст**` — выделение цветом
(так подсвечены цифры). Всё остальное экранируется, сырой HTML туда не
попадёт. Поле `updated` — дата под страницей, её стоит менять вместе с текстом.

Ответы написаны по интервью и по реальным цифрам каталога. Если поменяется
число треков или артистов — цифры в `faq.json` придётся поправить руками,
они там текстом.

## Что ещё стоит доделать

1. **Цвет** — в `site.json` → `theme.accent` сейчас янтарный `#e0a33c`, выбран за тебя.
2. **Порядок плиток** — поле `featured` в `site.json`: список Spotify-id тех работ,
   которые должны идти первыми. Сейчас пусто, порядок как в плейлисте.
3. **Жанры** — проверь `artist_genres.json`. Треки КАССЫ, RARA, ISB и Rychovaa
   положены в поп по догадке.
4. **Домен** — когда купишь, добавь файл `CNAME` с одной строкой (домен) и пропиши
   CNAME-запись у регистратора на `artkachev.github.io.`. В `site.json` → `url`
   поменяй адрес и пересобери, иначе ссылки в sitemap останутся старыми.
5. **Счётчик посещений** — заведи Google Analytics, код вида `G-XXXXXXX`
   впиши в `site.json` → `analytics`.

## Логотип и иконки

Всё лежит в `assets/` и подключается через `site.json`:

| Поле | Файл | Что это |
|---|---|---|
| `logo` | `assets/logo.svg` | Знак в шапке. Встраивается в страницу, цвет берёт от темы — см. ниже |
| `logo_wordmark` | — | `true` — знак рядом со словом КАССА, `false` — только знак |
| `icons.svg` | `assets/favicon.svg` | Иконка вкладки: тот же знак на тёмном квадрате |
| `icons.png` | `assets/favicon-32.png` | Запасная иконка для старых браузеров |
| `icons.apple` | `assets/apple-touch-icon.png` | Иконка при добавлении сайта на экран айфона |
| `og_image` | `assets/og.png` | Превью 1200×630, видно при отправке ссылки в чат |
| `og_image_size` | — | `[1200, 630]`. Ставится только общей картинке: у страницы трека превью — квадратная обложка |

У `logo.svg` холст обрезан по краям рисунка (`viewBox="25 35 135 82"`). В исходнике
знак занимал половину высоты холста и в шапке выглядел мелким — если будешь менять
файл, обрежь так же, иначе размер поедет.

**Про цвет знака.** В самом файле стоит обычный светлый `fill="#f4f1ee"` — так он
виден, если открыть файл отдельно. В шапку сборщик не подключает картинку тегом
`img`, а вставляет содержимое svg прямо в страницу, и там заливку перекрывает
`.logomark path{fill:currentColor}` — знак берёт цвет темы.

Не заменяй `#f4f1ee` в файле на `currentColor`: внутри `img` svg — отдельный
документ, `currentColor` не видит страницу и становится чёрным. На тёмном фоне
знак просто пропадает. Ровно так один раз и вышло.

## Чего не делать (уроки credits)

- **Не править собранный HTML.** На credits так и вышло: правили `index.html`
  напрямую, сборщик разошёлся с сайтом и теперь его запуск затирает дизайн.
  Здесь источник истины — `data.json` и `site.json`, HTML только пишется.
- **Не убирать обложки из репозитория.** Серверы Spotify (`i.scdn.co`) закрыты
  из России. Если ссылаться на них напрямую, у половины посетителей будут дыры.
  Новые обложки: `build` соберёт `covers/ids.txt`, дальше вкладка Actions →
  fetch-covers → Run workflow, и они приедут в репозиторий сами.
- **Не подключать шрифты с чужих CDN.** Только Google Fonts. На credits шрифт
  берётся с сервера Тильды — он платный и чужой.
- **Не переименовывать репозиторий.** Имя `artkachev.github.io` = адрес сайта.
- **Не удалять `.nojekyll`** — без него GitHub ломает сборку на JSON-файлах.

## Как устроен деплой

Пуш в `main` → workflow «Deploy static site to Pages» → сайт обновился, минуты три.
Смотреть: вкладка Actions. Настройка Pages: Source = GitHub Actions.

## Проверка перед тем, как считать готовым

Собрать и посмотреть локально:

```bash
python3 skill/scripts/portfolio.py --project . build && python3 -m http.server 8765
```

Дальше открыть `http://localhost:8765` и пройтись глазами: главная открывается,
обложки видны, плитка альбома открывает окно со списком треков, `/track/`
показывает артистов по алфавиту, `/faq/` раскрывает ответы, страница трека
открывается по прямой ссылке. На живом сайте ещё проверить, что плеер играет
на телефоне и ссылка в телеграме показывает превью.
