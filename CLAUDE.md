# КАССА — сайт работ

Портфолио Артема Ткачева: витрина треков с обложками и плеером плюс отдельная
страница на каждый трек. Живой адрес: https://credits.kaccamusic.com

Сделано по образцу credits.podlesnytwins.com, но с исправленными ошибками той
архитектуры — см. «Чего не делать».

## Из чего состоит

| Файл | Что внутри |
|---|---|
| `site.json` | Кто ты: имя, настоящее имя (`real_name`), подпись, цвет, шрифты, роли, жанры, контакты |
| `data.json` | Работы: 86 релизов — 81 сингл и 5 альбомов, всего 100 треков |
| `faq.json` | Вопросы и ответы: разделы, вопросы, ответы, «коротко» |
| `artist_genres.json` | Артист → жанр, чтобы импорт сам расставлял фильтры |
| `artist_names.json` | Артист → кириллическое написание, для страниц `/artist/`. Необязательный |
| `covers/` | Обложки. Лежат в репозитории, а не грузятся со Spotify |
| `skill/` | Скрипты сборки. Чистый Python, ставить ничего не надо |
| `index.html`, `track/`, `artist/`, `faq/`, `sitemap.xml`, `robots.txt`, `llms.txt` | **Собираются скриптом. Руками не править** |

## Какие есть страницы

- **`/`** — витрина плитками. Сверху два ряда фильтров. Жанр — один из списка.
  Первое нажатие на обложку заодно заряжает трек в плеер, не включая звук:
  телефон разрешает автозапуск только внутри жеста пользователя, а загрузка
  идёт не мгновенно, поэтому раньше приходилось жать дважды.
  Ролей можно выбрать сразу несколько, и работа должна нести их все:
  «продакшн + сведение» показывает 61 работу, где сделано и то, и другое, —
  это не сумма двух списков. Ряды работают вместе, поэтому «поп + продакшн»
  тоже пересечение. Числа у кнопок живые: показывают, сколько останется,
  если включить этот фильтр поверх уже выбранных; кнопка, ведущая в ноль,
  гаснет. Роль альбома — объединение ролей его треков. Сингл играет в два шага:
  нажатие на обложку только выбирает трек и зажигает кнопки, звук запускает
  уже плей — случайное касание ничего не включает. Рядом с плеем — ссылка
  «О треке» на страницу трека; на компьютере обе появляются и по наведению.
  Плеер трогает только кнопка плей: наведение и выбор чужой обложки не
  подменяют то, что играет. Альбом — одна
  плитка с бейджем «N треков», по клику открывается окно со списком.
- **`/track/`** — каталог работ: артисты по алфавиту, у каждого сначала
  альбомы со списком треков, потом синглы с годами. Указатель по буквам сверху.
  Есть поиск по артисту, альбому и названию трека. Он понимает и кириллицу,
  и латиницу в обе стороны: «клава» находит «Klava Koka». Работает это так —
  сборщик кладёт в `data-s` и сам текст, и его латиницу, а `hub.js`
  переводит запрос и сверяет с обеими формами.
- **`/track/<слаг>/`** — страница трека: обложка, роли, плеер, разметка
  MusicRecording для поиска. Авторство подписано как «КАССА (Артем Ткачев)» —
  настоящее имя берётся из `site.json` → `real_name`, оно же уходит в разметку
  как `alternateName`, чтобы поиск связал рабочее имя с настоящим. Убери поле —
  останется одно рабочее имя, строка не сломается.
  Имя пишется «Артем» — через `е`, без `ё`. В остальных словах `ё` остаётся.
- **`/artist/<слаг>/`** — страница артиста: прямой ответ на запрос вида
  «кто сводит [артиста]». У страницы трека такой заголовок уже был, но только
  про одну песню — а на вопрос про артиста в целом ни одна страница раньше не
  отвечала напрямую. Заголовок и `<h1>` — «Кто спродюсировал треки — Артист»,
  дальше список всех его треков со своими ролями и ссылками на страницы
  треков. Роль в заголовке — по тому же старшинству `write > prod > mix >
  master`, что и у трека, только собранная по всем его работам разом.
  Имя артиста в заголовке — после тире, не как дополнение к глаголу: склонять
  по падежам полсотни имён негде и незачем («Асию» вместо «Асия» никто не
  посчитает), тире снимает вопрос падежа.

  Кириллическое написание артиста, которого официально пишут латиницей
  (`Klava Koka`), берётся из необязательного `artist_names.json` — плоский
  словарь `{"Klava Koka": "Клава Кока"}`. Без записи страница обходится одной
  латиницей, страницы не разваливаются. С записью в заголовке и тексте
  появляются обе формы — так по-русски написанный запрос находит текст
  напрямую, а не только через морфологию поисковика.

  С каждой страницы трека и из шапки каждого артиста в `/track/` есть ссылка
  на его страницу артиста — это внутренние ссылки, которые её усиливают.
- **`/faq/`** — вопросы и ответы, собираются из `faq.json`, размечены
  как FAQPage.
- **`/llms.txt`** — краткая карта сайта для ИИ-поисковиков (ChatGPT, Perplexity
  и т.п.), формат [llmstxt.org](https://llmstxt.org): кто это, ссылки на
  разделы и список всех треков с ролями и годом простым markdown-списком, без
  разбора вёрстки. Собирается вместе с остальным сайтом, руками не правится.

## Команды

```bash
python3 skill/scripts/portfolio.py --project . build              # пересобрать
python3 skill/scripts/portfolio.py --project . check              # что не так на страницах
python3 skill/scripts/portfolio.py --project . publish --confirm  # собрать и залить
python3 skill/scripts/portfolio.py --project . import "<ссылка Spotify>"
python3 skill/scripts/portfolio.py --project . roles roles.txt
```

С Claude Code можно просто словами: «добавь на сайт <ссылка>».

## Роли

У каждого трека в `data.json` есть поле `roles`. Они проставлены по всем ста
трекам из списка Артема, менять нужно только при добавлении новых. Значения:

- `write` — написал
- `prod` — спродюсировал
- `mix` — свёл
- `master` — мастеринг

Можно несколько: `"roles": ["write", "prod", "mix"]`.

**Почему это важно.** Заголовок страницы трека берётся от первой роли по
старшинству `write > prod > mix > master`: «Кто написал», «Кто спродюсировал»,
«Кто свёл». Сейчас 77 страниц называются «кто спродюсировал» и 23 «кто свёл» —
это разные поисковые запросы. Именно страницы треков приносят людей из поиска,
поэтому у нового трека роль лучше ставить сразу, а не оставлять заглушку.

Пачкой удобнее через файл `roles.txt`, по строке на трек:

```
Журавли — Klava Koka — продакшн, сведение
Трезво — КАССА — написал, спродюсировал, свёл
```

Потом `roles roles.txt` → `build` → `publish --confirm`.
Строки, которые не совпали с названием, скрипт напечатает и не тронет.

## Альбомы

Релиз в `data.json` бывает двух видов. Сингл — `"type": "single"` с полем `id`.
Альбом — `"type": "album"` с `album_id` и списком `tracks`, у каждого трека
свой `id`, `title`, `artist` и роли. Страница у каждого трека альбома всё равно
своя, слаг тот же, что был у сингла, — старые ссылки не ломаются.

Сейчас альбомов пять: они собраны по хешу обложки (у треков одного релиза она
общая — это надёжнее поиска по названию), а названия взяты из открытого API
Deezer. Если появится ещё один альбом, проще всего импортировать его ссылкой:

```bash
python3 skill/scripts/portfolio.py --project . import "<ссылка на альбом Spotify>"
```

У сингла может быть поле `"album": "Название"` — тогда на странице трека
появится строчка «Из альбома «…»». Плитку это не меняет.

## Описание трека

Строка под заголовком страницы трека собирается сама: «Журавли» — Klava Koka,
JONY, 2026 год. Продакшн, сведение: КАССА (Артем Ткачев). Её можно заменить
своим текстом — поле `"about"` у сингла или у трека альбома в `data.json`:

```json
{"id": "...", "title": "Журавли", "about": "Свёл и спродюсировал зимой 2026-го.\n\nВокал писали в три подхода."}
```

Пусто или нет поля — строка собирается как раньше, страницы не меняются ни на
байт. Свой текст заменяет её и на странице, и в описании для поиска
(`<meta name="description">`, обрезается через `clamp`). Пустая строка внутри
разбивает текст на абзацы. Разметка не поддерживается, всё экранируется.

Автотекст строит `render.auto_lead()` — им же пользуется песочница, чтобы
показать подсказку в пустом поле.

Правится удобнее всего в песочнице, а не руками в `data.json`.

## Вопросы и ответы

Всё содержимое — в `faq.json`, HTML собирается из него. Структура: разделы,
внутри каждого список `{"q": вопрос, "a": ответ}`. В ответах работает
мини-разметка: `[текст](ссылка)` — ссылка, `**текст**` — выделение цветом
(так подсвечены цифры). Всё остальное экранируется, сырой HTML туда не
попадёт. Поле `updated` — дата под страницей, её стоит менять вместе с текстом.

Ответы написаны по интервью и по реальным цифрам каталога. Если поменяется
число треков или артистов — цифры в `faq.json` придётся поправить руками,
они там текстом.

## Что ещё стоит доделать

1. **Цвет** — в `site.json` → `theme.accent` сейчас янтарный `#e0a33c`, выбран за тебя.
2. **Порядок плиток** — поле `featured` в `site.json`: список Spotify-id тех работ,
   которые должны идти первыми. Сейчас пусто, порядок как в плейлисте.
3. **Жанры** — проверь `artist_genres.json`. Треки КАССЫ, RARA, ISB и Rychovaa
   положены в поп по догадке.
4. **Домен** — сделано: сайт живёт на `credits.kaccamusic.com`. В корне лежит
   файл `CNAME`, у reg.ru стоит CNAME-запись `credits` → `artkachev.github.io.`,
   в `site.json` → `url` прописан новый адрес. Старый `artkachev.github.io`
   GitHub сам перекидывает на новый. Меняешь домен — правь оба места и пересобирай,
   иначе canonical и sitemap останутся со старым адресом.
5. **Счётчик посещений** — заведи Google Analytics, код вида `G-XXXXXXX`
   впиши в `site.json` → `analytics`.
6. **Поисковые панели вебмастера** — сделано: сайт подтверждён в Google Search
   Console, Яндекс.Вебмастере и Bing Webmaster Tools (Bing — импортом из Google
   Search Console, без отдельного кода). Заводить их может только владелец
   (нужен вход в свой Google/Яндекс/Microsoft-аккаунт), но подтверждение прав
   встроено в сайт: в каждой панели выбери способ подтверждения «HTML-тег», скопируй код из
   `content="..."` и впиши в `site.json` → `verification.google` /
   `.yandex` / `.bing` (без кавычек площадки, только сам код). Дальше
   `build` → `publish --confirm` — метатег появится на всех страницах, и
   кнопка «Проверить» в панели сработает. После подтверждения там же отправь
   `sitemap.xml` (`https://credits.kaccamusic.com/sitemap.xml`) — так поисковик
   узнаёт о всех страницах треков сразу, а не только по ссылкам.

   Google иногда вместо кода предлагает скачать файл `google<набор символов>.html` —
   тогда способ другой: файл кладётся в корень репозитория как есть (без
   изменений) и прописывается в `publish.py` → `MANAGED_PATHS`, чтобы заливка
   его не проигнорировала. Сборщик его не создаёт и не удаляет.

## Логотип и иконки

Всё лежит в `assets/` и подключается через `site.json`:

| Поле | Файл | Что это |
|---|---|---|
| `logo` | `assets/logo.svg` | Знак в шапке. Встраивается в страницу, цвет берёт от темы — см. ниже |
| `logo_wordmark` | — | `true` — знак рядом со словом КАССА, `false` — только знак |
| `icons.svg` | `assets/favicon.svg` | Иконка вкладки: тот же знак на тёмном квадрате |
| `icons.png` | `assets/favicon-32.png` | Запасная иконка для старых браузеров |
| `icons.apple` | `assets/apple-touch-icon.png` | Иконка при добавлении сайта на экран айфона |
| `og_image` | `assets/og.png` | Превью 1200×630, видно при отправке ссылки в чат |
| `og_image_size` | — | `[1200, 630]`. Ставится только общей картинке: у страницы трека превью — квадратная обложка |

У `logo.svg` холст обрезан по краям рисунка (`viewBox="25 35 135 82"`). В исходнике
знак занимал половину высоты холста и в шапке выглядел мелким — если будешь менять
файл, обрежь так же, иначе размер поедет.

**Про цвет знака.** В самом файле стоит обычный светлый `fill="#f4f1ee"` — так он
виден, если открыть файл отдельно. В шапку сборщик не подключает картинку тегом
`img`, а вставляет содержимое svg прямо в страницу, и там заливку перекрывает
`.logomark path{fill:currentColor}` — знак берёт цвет темы.

Не заменяй `#f4f1ee` в файле на `currentColor`: внутри `img` svg — отдельный
документ, `currentColor` не видит страницу и становится чёрным. На тёмном фоне
знак просто пропадает. Ровно так один раз и вышло.

## Чего не делать (уроки credits)

- **Не править собранный HTML.** На credits так и вышло: правили `index.html`
  напрямую, сборщик разошёлся с сайтом и теперь его запуск затирает дизайн.
  Здесь источник истины — `data.json` и `site.json`, HTML только пишется.
- **Не убирать обложки из репозитория.** Серверы Spotify (`i.scdn.co`) закрыты
  из России. Если ссылаться на них напрямую, у половины посетителей будут дыры.
  Новые обложки: `build` соберёт `covers/ids.txt`, дальше вкладка Actions →
  fetch-covers → Run workflow, и они приедут в репозиторий сами.
- **Не подключать шрифты с чужих CDN.** Только Google Fonts. На credits шрифт
  берётся с сервера Тильды — он платный и чужой.
- **Не переименовывать репозиторий.** Имя `artkachev.github.io` — запасной адрес
  Pages, с него идёт переадресация на `credits.kaccamusic.com`.
- **Не удалять `.nojekyll`** — без него GitHub ломает сборку на JSON-файлах.
- **Не удалять `CNAME`** — без него Pages забывает домен и уходит на `.github.io`.

## Как устроен деплой

Пуш в `main` → workflow «Deploy static site to Pages» → сайт обновился, минуты три.
Смотреть: вкладка Actions. Настройка Pages: Source = GitHub Actions.

## Песочница

Черновик сайта, где можно править роли, жанры и видимость и складывать новые
треки, ничего не меняя на живом сайте:

https://claude.ai/code/artifact/e5140390-31a5-4e97-92ad-f276be3d5dbc

Страница приватная, открывается под учёткой Артема с любого устройства. Она
не ходит в репозиторий и не умеет ничего заливать — только копит список правок
внутри себя. Устроено это так: правки лежат JSON-ом в самой странице
(`<script id="state">`), и она публикует свою новую версию через
`claude.use("artifact")`.

**Когда именно записывается.** Публикация перезагружает все открытые окна
артефакта, включая то, в котором сидит человек. Сначала запись висела на паузе
в наборе — и страница перезагружалась прямо посреди набора описания, дописать
было невозможно. Поэтому правки копятся молча, а запись происходит в момент
закрытия окна трека (кнопка «Сохранить и закрыть», крестик, Escape, клик по
фону) плюс страховкой при уходе со вкладки. Пока правка не записана, в нижней
панели так и написано. **Не вешать запись на ввод текста.** Каталог с обложками (86 миниатюр по
72px, ~240 КБ) вшит туда же — со страницы артефакта картинки с
`credits.kaccamusic.com` не грузятся, внешние запросы там запрещены.

**Кнопка «Отдать правки Клоду».** На вкладке «Сводка». Она не вызывает Клода
напрямую — страница этого не умеет. Она ставит в состояние поле `ready` с
временем и публикует новую версию, а публикация присылает уведомление в
открытый разговор Claude Code. Увидел уведомление — прочитай состояние: если
`ready` не пустое, забирай правки, не дожидаясь отдельной просьбы. Если пустое,
человек ещё правит, трогать не надо.

Любая следующая правка сбрасывает `ready` в `null`: список изменился, и прежняя
отдача относилась уже не к нему. Поэтому забирать можно только то, что отдано.

Работает, пока разговор открыт. Если закрыт — уведомление никто не увидит,
и тогда обычный путь: написать в новом чате «забирай правки из песочницы».

**Как забрать правки.** Артем говорит «забирай правки из песочницы» или жмёт
кнопку. Дальше:

1. Прочитать страницу: `Artifact` с `action: "read"` и этим адресом.
2. Достать `<script id="state" type="application/json">` — там `edits` и
   `adds` — и положить в файл.
3. Перенести в данные:

   ```bash
   python3 skill/scripts/portfolio.py --project . apply /tmp/state.json
   ```

   Команда сама разложит правки: `about`, `genre`, `hidden` — в `data.json`,
   роли — в `roles.txt` (в `data.json` их писать нельзя, следующий прогон
   списка вернёт как было). В ответе видно, что изменилось, и `unmatched` —
   слаги, которых в каталоге не нашлось.
4. `adds` она не выполняет, только показывает: ссылки прогнать через `import`
   с нужной ролью.
5. `build` → `check` → `publish`.
6. Пересобрать саму песочницу из свежих данных **с пустым состоянием** и
   опубликовать по тому же адресу — иначе она останется со старым каталогом
   и покажет уже применённые правки как ещё не выкаченные.

Форма правки: ключ — слаг страницы, внутри только изменённые поля `roles`,
`about`, `genre`, `hidden` и `tracks` — правки треков альбома по индексу,
вида `{"0": {"roles": [...], "about": "..."}}`. Рядом с `edits` и `adds` лежит
`ready` — отметка кнопки.

Пересобирать песочницу после применения нужно с пустым состоянием, включая
`ready`, иначе она покажет уже выкаченное как отданное.

Собирается одной командой — каталог берётся из `data.json` и `site.json`,
миниатюры делает `sips` из `covers/`:

```bash
python3 skill/scripts/portfolio.py --project . sandbox --out /tmp/sandbox.html
```

Если в песочнице остались непримененные правки, их надо перенести в новую
версию, иначе они пропадут: сохранить состояние в файл и собрать с ним.

```bash
python3 skill/scripts/portfolio.py --project . sandbox \
  --out /tmp/sandbox.html --state /tmp/state.json
```

Готовый файл публикуется артефактом **по тому же адресу**, иначе появится
вторая песочница. Исходники страницы — `skill/templates/sandbox.html`
(разметка и стили) и `skill/templates/sandbox.js` (логика). Сам файл сборки
в репозиторий не кладётся, он в `.gitignore`.

`sips` есть только на macOS. На другой системе обложки вшиваются исходными,
и страница раздувается с 277 КБ до девяти мегабайт — это уже за пределом
артефакта в 16 МБ вместе с base64.

## Проверки при сборке

`skill/scripts/checks.py` смотрит данные и то, что из них собралось. Появился
он не от любви к порядку: на живой сайт уже уехали кириллическая «В» в слове
«Вonus» (в адрес она ушла как `vonus`) и описание FAQ, обрезанное посреди
имени — «VERBEE, Kla». Такие мелочи сразу выдают, что страницы собрали
скриптом и не прочитали глазами.

Два уровня. **`стоп`** — `publish` откажется заливать (обойти можно флагом
`--ignore-checks`, но лучше починить). **`глянь`** — просто печатается,
решает человек.

| Проверка | Уровень | Что ищет |
|---|---|---|
| Алфавиты | стоп | Кириллица и латиница внутри одного слова |
| Мета | стоп / глянь | Пустое или оборванное на полуслове описание; заголовок длиннее 60, описание вне 70–160 |
| Дубли | стоп / глянь | Один адрес собран дважды, один id у разных треков, одинаковые названия у артиста |
| Дефисы | глянь | « - », «--», « – » в названиях |
| Осиротевшие папки | глянь | Папка в `track/`, которую сборка больше не делает |

Заголовки и описания линтер берёт не из готового HTML, а из того, что
сборщик передал в `render.head` — HTML по-прежнему только пишется и никогда
не разбирается обратно.

Часть находок уровня «глянь» — это нормально и трогать их не надо: « - » в
«Miss Cali (Hallelujah) - Imanbek Remix» — официальное название с площадки,
а длинные заголовки у ремиксов просто такие и есть.

## Скрытые работы

Флажок в песочнице ставит работе `"hidden": true`. Он убирает её **только с
витрины** — с плиток на главной. Всё остальное остаётся: своя страница
собирается как обычно, работа стоит в каталоге `/track/`, на странице артиста,
в `sitemap.xml` и в `llms.txt`. Так и задумано: страницы треков — то, что
приводит людей из поиска, и терять их из-за порядка на главной незачем.

Раньше фильтр стоял в `order_releases` безусловно, а через него идёт
`track_entries`, то есть вообще всё. Скрытая работа выпадала разом отовсюду,
а уже залитая страница оставалась лежать в репозитории: её никто больше не
обновлял, и ни одной ссылки на неё не вело — ни из каталога, ни из карты
сайта. Для индексации это худший расклад. Теперь фильтр зовёт только
`render_index`, а каталог и страницы берут работы вместе со скрытыми.

Проверить, что ничего не съехало: скрытой работы не должно быть в `index.html`
и она должна быть в `sitemap.xml`, `track/index.html` и `llms.txt`.
Сколько работ убрано с витрины, сборка печатает строкой `off_grid`.

**Про осиротевшие папки.** Слаг считается от названия, поэтому починка
опечатки меняет адрес страницы. Старая папка остаётся в репозитории и
продолжает отдаваться поиском. Так вышло с
`track/klava-koka-ya-ne-otdam-tebya-nikomu-vonus-track/` — там теперь лежит
заглушка с переадресацией на новый адрес, написанная руками. Сборщик её не
делает и не трогает, а линтер такие заглушки узнаёт по `http-equiv="refresh"`
и молчит про них.

## Проверка перед тем, как считать готовым

Собрать и посмотреть локально:

```bash
python3 skill/scripts/portfolio.py --project . build && python3 -m http.server 8765
```

Дальше открыть `http://localhost:8765` и пройтись глазами: главная открывается,
обложки видны, плитка альбома открывает окно со списком треков, `/track/`
показывает артистов по алфавиту, `/faq/` раскрывает ответы, страница трека
открывается по прямой ссылке. На живом сайте ещё проверить, что плеер играет
на телефоне и ссылка в телеграме показывает превью.
