# КАССА — сайт работ

Портфолио Артёма Ткачева: витрина треков с обложками и плеером плюс отдельная
страница на каждый трек. Живой адрес: https://artkachev.github.io

Сделано по образцу credits.podlesnytwins.com, но с исправленными ошибками той
архитектуры — см. «Чего не делать».

## Из чего состоит

| Файл | Что внутри |
|---|---|
| `site.json` | Кто ты: имя, подпись, цвет, шрифты, роли, жанры, контакты |
| `data.json` | Работы: 100 треков — артист, название, год, жанр, роли, обложка |
| `artist_genres.json` | Артист → жанр, чтобы импорт сам расставлял фильтры |
| `covers/` | Обложки. Лежат в репозитории, а не грузятся со Spotify |
| `skill/` | Скрипты сборки. Чистый Python, ставить ничего не надо |
| `index.html`, `track/`, `sitemap.xml`, `robots.txt` | **Собираются скриптом. Руками не править** |

## Команды

```bash
python3 skill/scripts/portfolio.py --project . build              # пересобрать
python3 skill/scripts/portfolio.py --project . publish --confirm  # собрать и залить
python3 skill/scripts/portfolio.py --project . import "<ссылка Spotify>"
python3 skill/scripts/portfolio.py --project . roles roles.txt
```

С Claude Code можно просто словами: «добавь на сайт <ссылка>».

## Роли — главное, что стоит доделать

У каждого трека в `data.json` есть поле `roles`. Сейчас у всех ста стоит `mix`,
потому что при импорте роли неизвестны. Значения:

- `write` — написал
- `prod` — спродюсировал
- `mix` — свёл
- `master` — мастеринг

Можно несколько: `"roles": ["write", "prod", "mix"]`.

**Почему это важно.** Заголовок страницы трека берётся от первой роли:
«Кто написал», «Кто спродюсировал», «Кто свёл». Сейчас все сто страниц
называются одинаково — «кто свёл». Как проставишь, часть станет
«кто спродюсировал» и «кто написал», и это разные поисковые запросы.
На credits именно страницы треков приносят людей из поиска.

Пачкой удобнее через файл `roles.txt`, по строке на трек:

```
Журавли — Klava Koka — продакшн, сведение
Трезво — КАССА — написал, спродюсировал, свёл
```

Потом `roles roles.txt` → `build` → `publish --confirm`.
Строки, которые не совпали с названием, скрипт напечатает и не тронет.

## Что ещё стоит доделать

1. **Цвет** — в `site.json` → `theme.accent` сейчас янтарный `#e0a33c`, выбран за тебя.
2. **Логотип** — сейчас имя набрано шрифтом. Если есть SVG, положи в `assets/`
   и укажи в `site.json` → `logo`.
3. **Картинка для превью** — то, что видно, когда кидаешь ссылку в чат.
   Горизонтальная, от 1200×630, в `assets/`, путь в `og_image`.
4. **Порядок плиток** — поле `featured` в `site.json`: список Spotify-id тех работ,
   которые должны идти первыми. Сейчас пусто, порядок как в плейлисте.
5. **Жанры** — проверь `artist_genres.json`. Треки КАССЫ, RARA, ISB и Rychovaa
   положены в поп по догадке.
6. **Домен** — когда купишь, добавь файл `CNAME` с одной строкой (домен) и пропиши
   CNAME-запись у регистратора на `artkachev.github.io.`. В `site.json` → `url`
   поменяй адрес и пересобери, иначе ссылки в sitemap останутся старыми.
7. **Счётчик посещений** — заведи Google Analytics, код вида `G-XXXXXXX`
   впиши в `site.json` → `analytics`.

## Чего не делать (уроки credits)

- **Не править собранный HTML.** На credits так и вышло: правили `index.html`
  напрямую, сборщик разошёлся с сайтом и теперь его запуск затирает дизайн.
  Здесь источник истины — `data.json` и `site.json`, HTML только пишется.
- **Не убирать обложки из репозитория.** Серверы Spotify (`i.scdn.co`) закрыты
  из России. Если ссылаться на них напрямую, у половины посетителей будут дыры.
  Новые обложки: `build` соберёт `covers/ids.txt`, дальше вкладка Actions →
  fetch-covers → Run workflow, и они приедут в репозиторий сами.
- **Не подключать шрифты с чужих CDN.** Только Google Fonts. На credits шрифт
  берётся с сервера Тильды — он платный и чужой.
- **Не переименовывать репозиторий.** Имя `artkachev.github.io` = адрес сайта.
- **Не удалять `.nojekyll`** — без него GitHub ломает сборку на JSON-файлах.

## Как устроен деплой

Пуш в `main` → workflow «Deploy static site to Pages» → сайт обновился, минуты три.
Смотреть: вкладка Actions. Настройка Pages: Source = GitHub Actions.

## Проверка перед тем, как считать готовым

```bash
cd skill && python3 -m unittest discover -s tests
```

И живой сайт: главная открывается, обложки видны, плеер играет на телефоне,
страница трека открывается по прямой ссылке, ссылка в телеграме показывает превью.
