# Сайт-портфолио музыканта

Делает персональный сайт работ по образцу credits.podlesnytwins.com, но с брендом,
цветом и треками конкретного человека. Сайт живёт в **его** репозитории на GitHub.

## Что получается

- Главная: сетка обложек, фильтры по жанрам, плеер Spotify, контакты.
- Страница на каждый трек — под запросы вида «кто свёл такой-то трек».
- Список всех треков, `sitemap.xml`, `robots.txt`, разметка Schema.org, превью для мессенджеров.
- Ни сборки, ни фреймворков, ни зависимостей: чистый Python и статические файлы.

## Устройство проекта

Проект — папка, повторяющая репозиторий владельца. Обычно `~/portfolio-sites/<ник>/`.

| Файл | Что внутри |
|---|---|
| `site.json` | Кто это: имя, подпись, репозиторий, адрес, цвет, шрифты, роли, жанры, контакты |
| `data.json` | Работы: синглы и альбомы с обложками, годами, жанрами и ролями |
| `artist_genres.json` | Артист → жанр, чтобы импорт сам расставлял фильтры |
| Остальное | Собранный сайт: `index.html`, `track/`, `covers/`, `sitemap.xml` |

Готовый HTML **только пишется**. Никогда не разбирай его обратно как источник
данных — правь `data.json` и пересобирай. На credits эту границу когда-то
нарушили, и сборщик разошёлся с сайтом.

## Порядок работы

```bash
SCRIPT=<skill-base>/scripts/portfolio.py
P=~/portfolio-sites/<ник>

python3 "$SCRIPT" --project "$P" import "<ссылка на плейлист, альбом или трек>" --json
python3 "$SCRIPT" --project "$P" build
python3 "$SCRIPT" --project "$P" roles roles.txt      # когда владелец пришлёт роли
python3 "$SCRIPT" --project "$P" publish --confirm --message "Обновить сайт"
```

Ключи `import`: `--role write|prod|mix|master` (по умолчанию `mix`),
`--genre POP|HIPHOP|...`, `--force-album` для настоящего альбома из одного трека.

Файл ролей — строки вида `Название — артист — продакшн, сведение`.
Неузнанные строки печатаются и не применяются.

## Новый сайт с нуля

1. Собрать данные у человека по списку: плейлист Spotify, роли, имя и подпись,
   контакты, ник на GitHub, цвет, логотип.
2. Владелец создаёт репозиторий **с именем, равным своему нику**
   (`ник.github.io`) — тогда адрес без хвостов и домен прикручивается позже
   без переделок. Добавляет тебя соавтором. В Settings → Pages ставит
   Source: GitHub Actions (это может сделать только он — у соавтора нет прав на настройки).
3. Завести папку проекта, `git remote add origin`, написать `site.json`.
4. Разметить артистов по жанрам в `artist_genres.json`. Спорное выносить человеку списком.
5. `import` → `build` → показать превью → получить добро → `publish --confirm`.
6. Проверить живой сайт, а не вывод скрипта.
7. Передать владельцу: положить в репозиторий `CLAUDE.md` и `README.md`
   из [references/handoff.md](references/handoff.md).

## Границы при работе с чужим репозиторием

- Заливать только в репозиторий из `site.json` → `repo`. Проверка встроена в `publish.guard`.
- Трогать только пути из `publish.MANAGED_PATHS`.
- Первая заливка — с явного согласия человека. Без `--confirm` скрипт откажется.
- Настройки репозитория не трогаем: прав нет и не требуется.
- Токены и пароли не принимаем — только доступ соавтора.

## Правила содержания

- Обложки лежат в репозитории: серверы Spotify недоступны из России.
- Шрифты только Google Fonts с полной кириллицей. По умолчанию Oswald + Golos Text.
  Ничего с чужих CDN — там бывают платные лицензии.
- Порядок плиток задаётся полем `featured` в настройках, а не вёрсткой.
- Публичный эмбед Spotify отдаёт примерно первые 100 треков плейлиста.

## Проверка перед сдачей

```bash
cd <skill-base> && python3 -m unittest discover -s tests
```

Потом живой сайт: главная открывается, обложки видны, плеер играет,
страница трека доступна по прямой ссылке, ссылка в мессенджере показывает превью.
